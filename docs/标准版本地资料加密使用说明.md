# 标准版本地资料加密使用说明

> 本文档描述「汽车零部件数字设计平台（标准版）」的本地资料加密功能。
> 科研版不提供加密功能，不显示以下任何入口。

---

## 一、功能概述

标准版对**所有本地导出文件**自动进行 AES-256-GCM 加密。文件一旦离开本机（拷贝到 U 盘、移动硬盘，或通过微信 / 钉钉 / QQ 等网络媒介传输），打开时会显示乱码或提示「文件已加密，需解密」。

- **解密账号**：李华东（固定，不可修改）
- **解密密码**：首次导出时由用户自行设置，至少 6 个字符
- **加密文件后缀**：`.ctre`（如 `试验报告.pdf.ctre`）

### 加密范围与例外

以下场景的文件会被加密：

| 场景 | 出口 | 生成文件 |
|------|------|---------|
| Word 计算书导出 | 保存对话框 | `计算书.docx.ctre` |
| PDF 计算书导出 | 保存对话框 | `计算书.pdf.ctre` |
| Excel 计算汇总导出 | 保存对话框 | `全部计算汇总.xlsx.ctre` |
| CSV / JSON 导出 | 保存对话框 | 加 `.ctre` 后缀 |
| 试验报告原件导出 | 「试验报告检索」页「导出副本」 | 原文件名 + `.ctre` |
| CAE 分析报告导出 | 「CAE 报告检索」页「导出副本」 | 原文件名 + `.ctre` |

以下场景**不加密**（保持明文）：

- 软件内预览、检索、公式计算 — 全程明文
- 归档到服务器 UNC 产品数据库（`\\10.1.1.245\Product Database\...`）— 原文不变
- 科研版 — 全部本地导出均为明文

## 二、首次使用：设置解密密码

标准版首次执行任何本地导出操作时，会弹出「设置资料解密密码」窗口：

```
┌──────────────────────────────────────┐
│  首次导出：设置解密密码                │
│                                      │
│  标准版本地导出文件将使用 AES-256-GCM  │
│  自动加密。请妥善保管密码，在其他电脑  │
│  解密时需要使用。                     │
│                                      │
│  解密账号：李华东（固定）              │
│                                      │
│  解密密码（至少 6 个字符）：          │
│  ┌──────────────────────────────┐    │
│  └──────────────────────────────┘    │
│                                      │
│  确认解密密码：                       │
│  ┌──────────────────────────────┐    │
│  └──────────────────────────────┘    │
│                                      │
│  [ 设置并继续导出 ]  [ 取消导出 ]      │
└──────────────────────────────────────┘
```

操作要点：

1. 输入两次密码（至少 6 位），点击「设置并继续导出」
2. 密码通过 Electron safeStorage（Windows DPAPI）保存在本机，不写明文到磁盘
3. 点击「取消导出」可放弃本次导出；下次导出仍会再次弹出设密窗口
4. 密码一旦设置成功，之后本机导出不再弹窗，直接自动加密

> ⚠️ **重要：无密码也能打开加密文件。请将密码妥善保管（建议使用密码管理器记录）。**
> 
> 忘记密码时无法找回，只能在本机「设置 → 资料加密」中修改密码（修改后仅影响之后导出的文件）。

## 三、修改解密密码

打开软件 → 左侧导航 → **设置** → **资料加密（标准版）**：

```
┌─────────────────────────────────────────────────┐
│ 资料加密（标准版）                               │
│                                                  │
│ 解密账号    李华东                               │
│ 加密方式    AES-256-GCM                          │
│ 密码状态    已设置                               │
│                                                  │
│ [ 新解密密码 ]                                   │
│ [ 确认新解密密码 ]                               │
│ [ 修改密码 ]                                     │
└─────────────────────────────────────────────────┘
```

- 未设置密码时按钮显示「设置密码」
- 已设置密码时按钮显示「修改密码」
- 修改密码**不会解密**之前已导出的文件 — 旧文件仍需原密码解密

## 四、解密他人发来的 .ctre 文件

打开软件 → 左侧导航 → **设置** → **文件解密**：

```
┌─────────────────────────────────────────────────┐
│ 文件解密                                         │
│                                                  │
│ 本地下个解密账号：李华东                         │
│ 请输入密码，然后选择要解密的 .ctre 文件。         │
│                                                  │
│ 解密账号  [ 李华东           ]                   │
│ 解密密码  [ ************     ]                   │
│ [ 选择加密文件并解密 ]                            │
│                                                  │
│ 选择文件后会弹出「另存」对话框，解密后的明文文件   │
│ 写入指定位置，原 .ctre 文件不会被修改。           │
└─────────────────────────────────────────────────┘
```

操作步骤：

1. 解密账号填 **李华东**（已预填）
2. 输入导出方设置的解密密码
3. 点击「选择加密文件并解密」→ 在弹出的打开对话框中选中 `.ctre` 文件
4. 在随后弹出的「另存」对话框中选择明文文件的保存位置
5. 解密成功后，提示栏显示「已解密并保存：[完整路径]」

常见错误提示：

| 提示 | 原因 |
|------|------|
| 不是有效的 CTR 加密文件 | 选中的文件不是 `.ctre` 格式，或已损坏 |
| 解密账号或密码错误，或文件已损坏 | 账号不是「李华东」、密码不对、或文件被篡改 |
| 加密文件头无效或文件已损坏 | 容器头部 JSON 解析失败（文件截断） |

## 五、加密文件容器格式

每个 `.ctre` 文件是一个自描述的二进制容器，结构如下（按顺序排列）：

```
┌──────────────┬──────────┬─────────────────┬──────────┬──────────┬──────────┬──────────────┐
│ Magic        │ Header   │ JSON 头          │ Salt     │ Nonce    │ AuthTag  │ 密文         │
│ "CTRENC1"    │ 长度(4B) │ (变长)           │ 16 字节  │ 12 字节  │ 16 字节  │ (变长)        │
└──────────────┴──────────┴─────────────────┴──────────┴──────────┴──────────┴──────────────┘
```

JSON 头（UTF-8 明文，可直接用文本编辑器打开查看部分信息）包含：

| 字段 | 值 |
|------|---|
| version | `1` |
| notice | `本文件已加密，需解密后使用。解密账号：李华东` |
| originalName | 原始文件名（如 `试验报告.pdf`） |
| algorithm | `AES-256-GCM` |
| kdf | `PBKDF2-SHA256` |
| iterations | `150000` |

密钥派生：

```
passwordKey = PBKDF2("李华东" + ":" + password, salt, 150000, 32, SHA256)
```

- 加密/解密主体：`AES-256-GCM`
- AAD（附加认证数据）：JSON 头的 UTF-8 字节
- 密文后的 16 字节 AuthTag 同时校验：密钥正确性 + 文件完整性

GCM 的 AuthTag 天然承担了「密码错误检测」和「文件篡改检测」的双重功能 — 密码不对或文件被改动一字节，AuthTag 校验都会失败，解密直接报错，不会返回半明文。

## 六、技术说明（给开发/运维参考）

### 密码存储位置

本机设置的解密密码经 Electron `safeStorage.encryptString` 加密后写入：

```
%APPDATA%/汽车零部件数字设计平台（标准版）/ctr-data.json
```

`settings.encryption.encryptedPassword` 字段保存 base64 编码的 DPAPI 密文。

- safeStorage 在 Windows 上使用 DPAPI，密钥与当前 Windows 用户绑定
- 同一台电脑上换 Windows 用户登录，无法解密此密码（会被视为「未设置」）
- 重新安装系统或换主板/CPU 后，DPAPI 密钥可能失效

### 版本差异

| 功能 | 标准版 | 科研版 |
|------|--------|--------|
| 本地导出自动加密 | ✅ | ❌ |
| 设置页「资料加密」卡片 | ✅ 显示 | ❌ 隐藏 |
| 设置页「文件解密」卡片 | ✅ 显示 | ❌ 隐藏 |
| 服务器 UNC 归档 | 明文 | 明文 |
| 前端导航 | 剔除导入页 | 完整菜单 |

### 主进程 IPC 接口

仅标准版调用时生效，科研版返回拒绝消息：

| IPC 通道 | 功能 |
|----------|------|
| `encryption:status` | 读取加密状态（enabled / account / passwordConfigured） |
| `encryption:setPassword` | 设置或修改本机解密密码 |
| `encryption:cancelSetup` | 首次设密弹窗取消时通知主进程 |
| `encryption:decrypt` | 选择 `.ctre` 文件 → 验证账号密码 → 另存明文 |

### 模块清单

| 文件 | 职责 |
|------|------|
| `electron/fileEncryption.cjs` | 纯 Node 加密/解密逻辑，无 Electron 依赖，可独立测试 |
| `electron/main.cjs` | 在标准版拦截 5 个导出 IPC，首次导出弹窗设密 |
| `electron/preload.cjs` | 暴露 `window.ctr.encryption` 受控接口 |
| `src/api.ts` | 渲染层 TS 类型与浏览器 fallback |
| `src/pages/SettingsPage.tsx` | 标准版专属的加密设置与解密 UI |
| `tests/fileEncryption.test.ts` | 容器往返、错误处理、篡改检测单元测试 |

### 安全边界

本加密方案解决的是「文件离开本机后无法直接打开」的场景。以下威胁不在加密覆盖范围内：

- 软件内预览 / 下载时被恶意进程内存 dump（密文已在内存中还原）
- 攻击者能在本机运行软件（此时文件已明文）
- Windows safeStorage 被管理员绕过（DPAPI 密钥存储在系统中）

如需更严格的防泄漏（如打印管控、截屏审计、内核级文件过滤），需额外部署企业级 DLP 系统（亿赛通、IP-guard、明朝万达等），超出本软件加密能力范围。

## 七、常见问题

**Q：我设置的密码忘了怎么办？**

A：在本机「设置 → 资料加密」中重新设置密码即可。但**之前导出的 .ctre 文件仍需旧密码**才能解密，旧密码已丢失则无法恢复。建议重要资料导出后先在本机验证一次能正常打开，再离开本机。

**Q：科研版能解密 .ctre 文件吗？**

A：不能。加密/解密入口仅在标准版显示。如果需要在科研版机器上解密，请改用标准版打开「设置 → 文件解密」。或者，加密方在标准版上先解密出明文，再发送明文（不推荐，会破坏加密目的）。

**Q：我能不能让某台标准版机器不要加密？**

A：不能。只要安装的是标准版，本地导出就是加密的。如需不加密请安装科研版。

**Q：加密会很慢吗？**

A：不会。AES-256-GCM 是硬件加速的流密码，10MB 文件加密耗时在毫秒级。唯一较慢的步骤是 PBKDF2 派生密钥（约 150-200ms，每加密一次执行一次）。

**Q：可以用第三方工具解密 .ctre 文件吗？**

A：`.ctre` 是软件私有容器格式，没有公开的独立解密工具。必须使用标准版内置的解密功能。容器格式在第五节有详细描述，如需自行实现解密脚本可按该规范编写。
