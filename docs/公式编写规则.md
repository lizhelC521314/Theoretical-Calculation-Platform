# 公式编写规则

> 适用对象：在 `src/domains/` 下新增或修改计算公式的开发者。
> 类型定义以 [src/formula/types.ts](../src/formula/types.ts) 为准；单位分组以 [src/formula/units.ts](../src/formula/units.ts) 为准。
> 现成示例：`src/domains/structure/intakeHose.ts`（复杂反算 + 多输出分组的完整样板）。

---

## 1. 新增公式的完整流程（7 步）

1. **建文件**：在对应领域目录下新建 `src/domains/<domain>/<name>.ts`。
   - `<domain>` ∈ `fluid`（流体设计）/ `structure`（结构设计）/ `acoustics`（NVH 设计）。
2. **写元数据**：导出 `FormulaSpec` 对象，填 `id / domain / subsystem / title / summary / tags / description`。
3. **定义输入输出**：`inputs: ParamSpec[]`、`outputs: OutputSpec[]`（见第 3、4 节）。
4. **写公式展示**：`latex`（KaTeX，必填至少一条）+ `assumptions`（适用条件，必填至少一条）；可选 `diagram`（SVG 字符串，viewBox 建议 `0 0 400 220`，集中放各领域 `diagrams.ts`）、`curve`。
5. **实现 solve**：纯函数，SI 进 SI 出（见第 5 节）。
6. **配基准算例**：`benchmarks` 至少 1 条，**实跑取数**（见第 6 节铁律）。
7. **注册并验证**：在 `src/formula/registry.ts` import 并加入 `ALL_FORMULAS` → `npm run typecheck` → `npm test` → `npm run dev` 人工过一遍界面。

完成标志：测试全绿、界面能算出结果、CSV 导出正常、提交信息符合规范。

## 2. FormulaSpec 顶层字段规范

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | ✔ | 格式 `<domain>.<camelCaseName>`，全库唯一，注册表按键索引 |
| `domain` | ✔ | `fluid` / `structure` / `acoustics`，决定一级导航与标签色 |
| `subsystem` | ✔ | 二级导航分组名，如「进气系统」「消声器」 |
| `title` | ✔ | 界面主标题，中文，能独立看懂（如「橡胶进气软管（波纹管）几何反算设计」） |
| `summary` | ✔ | 一句话说明「输入什么、输出什么、解决什么问题」 |
| `tags` | ✔ | 搜索关键词，含别名、标准号（如 `SAE J20`、`EJMA`）、俗称 |
| `description` | ✔ | 详细说明：编号步骤写清计算流程，与 `latex` 的式号对应 |
| `inputs` / `outputs` | ✔ | 见下两节 |
| `latex` | ✔ | `{ label, tex }[]`，主公式行前加 `\star`；label 注明式号范围（如「壁厚取值（式10）」） |
| `assumptions` | ✔ | 适用条件与近似处理，每条一句话；**所有工程近似、限幅、经验修正必须写在这里** |
| `solve` | ✔ | 见第 5 节 |
| `benchmarks` | ✔ | 见第 6 节 |
| `diagram` | 可选 | SVG 字符串，放领域目录的 `diagrams.ts` |
| `curve` | 可选 | `compute(v)` 返回 **x 严格升序**的 `{x,y}[]`；与 solve 同样的 SI 入参 |
| `sensitivity` | 可选 | 默认开启。两点拟合/数据对强关联类公式必须显式 `sensitivity: false`（逐参数扫描会破坏数据对，物理上无意义） |

## 3. 输入参数 ParamSpec 规范

```ts
{ key: 'p', label: '工作压力', symbol: 'p', unit: 'kPa', unitGroup: 'pressure',
  default: 100, min: 0, required: true, description: '按工况，增压机型更高' }
```

- `key`：camelCase，`solve` 里按此取值；全公式内唯一，逐腔参数用 `Lc1, Lc2, …` 编号。
- `unit`：**界面默认显示单位**（工程习惯单位，如 mm、kPa、℃），`default/min/max` 都以此单位计。
- `unitGroup`：需要单位下拉换算时填，取值必须是 `UNIT_GROUPS` 里已有的组名；**没有合适的组就先扩展 `units.ts`**（见第 4 节），不要硬编码换算。
- 无单位参数：`unit: '-'`，不写 `unitGroup`。
- `default`：必填默认值（确保用户打开页面即有可算状态）。
- `min/max`：以 `unit` 为单位的**建议范围**，越界只做提示不拦截；物理硬约束（如「必须 > 0」）放到 `solve` 的合法性判断里。
- `required`：默认视为必填；`required: false` 仅用于「记录型」参数（不参与计算，如材料牌号）。
- `kind: 'select'` + `options`：枚举输入（如结构型式 1/2），`value` 是数值（SI 语义），`label` 是显示文本。
- `showIf: { key, min?, max? }`：条件显示，用于逐腔展开（腔数 n 之外的输入不渲染）。min/max 可单用（如型式切换 `max:1` / `min:2`）。
- `description`：一句话讲清物理含义、典型取值范围、来源；**用户靠它填数，不许省略**。

## 4. 输出参数与单位分组

```ts
{ key: 't', label: '壁厚（反算）', symbol: 't', unit: 'mm', unitGroup: 'length',
  digits: 2, group: '反算结果', primary: true, description: 't = max(tb, tv, tr)（式10）' }
```

- `unit` 填工程习惯显示单位；`unitGroup` 填后结果区会按 `autoUnit` 自动选单位（优先 `preferred`，量级极端自动缩放）。
- `digits`：显示小数位，按工程读数习惯给（壁厚 2 位、刚度 2 位、dB 1 位…）。
- `group`：相同分组名的输出在结果区集中并带小标题；推荐分组结构：`反算结果 / 中间量 / 校核·××`。
- `primary: true`：主结果高亮，每个公式 1~4 个，选用户最关心的。
- `showIf`：逐腔输出必须配 `showIf`，与输入侧同规则；未参与计算的腔对应输出**不要在 solve 里返回**（返回 `undefined`），三处显示（结果区/符号表/CSV）会自动隐藏。
- `description`：注明公式号与判定准则（「≥1 合格」「≤ Lp,req」）。

**扩展单位分组**（`units.ts`）规则：
- 组内 `si` 是基准单位，`units[].factor` 满足 `SI = 显示值 × factor`；
- `preferred` 是工程习惯回显单位；
- 平移型单位（目前只有 ℃）不进 factor 体系，在 `toSI/fromSI/autoUnit` 里加特例，并在 `temperatureDelta` 这类「温差」组单独处理；
- 新增组后补 `tests/units.test.ts` 用例。

## 5. solve 实现规范

```ts
solve(v) {
  const empty: Record<string, number> = { t: NaN, /* …全部输出 key… */ };
  const ok = v.D > 0 && v.E > 0 /* …全部物理硬约束… */;
  if (!ok) return empty;
  // …纯 SI 计算…
  return { t, N, L, /* … */ };
}
```

必须遵守：

1. **纯函数**：同输入同输出；不读文件、不访问网络、不碰界面状态、不写 `console`。
2. **SI 进 SI 出**：入参 `v` 已是 SI（界面已换算），返回值必须是 SI。**禁止**在 solve 内出现 `*1000`、`/1e6` 这类显示单位换算；公式里的经验系数本身含单位时，在 `assumptions` 注明。
3. **开头合法性检查**：所有会导致除零、开负数方、对数取负的输入先判断，不满足就返回**全 key 的 NaN 对象**（key 与 `outputs` 完全一致，保证界面行结构稳定）。发现无可行解（如约束区间为空）同样返回全 NaN，而不是抛错——界面会显示为空结果。
4. **迭代收敛**：反算类公式允许内部迭代，但必须设上限（如 20 轮）并以「相邻两轮关键量不变」为收敛条件；能解析求解的（如二次方程）优先解析解。
5. **数值稳定**：
   - 发散点附近做工程限幅（如辐射效率限幅到 [0,1]），并在 `assumptions` 说明；
   - 圆整规则（如壁厚向上圆整至 0.5 mm）写内部小函数，式号在注释里标清；
   - 中间无量纲判断避免 `=== 0`，用阈值。
6. **逐腔输出**：只返回实际参与计算的腔的 key（如 `alpha1…alpha5`），未参与的**不要返回**（`undefined`），配合 `showIf` 自动隐藏。
7. **注释标式号**：关键步骤注释对应参考文档式号（`// 波数下限（式15）`），与 `latex`、`description` 三处式号一致。
8. **性能**：solve 会被结果区、CSV 导出、敏感性扫描反复调用，单次应远低于毫秒级；敏感性分析会对每个输入逐点扫描，避免在 solve 内做无必要的大数组分配。

## 6. benchmarks 基准算例（铁律）

```ts
benchmarks: [{
  name: '反算算例：D50 / w12 / 2 层，自然吸气真空 30 kPa（真空塌陷约束控制）',
  input: { D: 0.05, /* …SI… */ pac: 100 },
  expect: { t: 0.006, N: 3, /* …SI 全精度值… */ },
  tolerance: 1e-9,
  source: '按参考文档式 (1)~(36) 自建反算算例：…',
}]
```

1. **input / expect 一律 SI 单位**，与 solve 的约定一致；不要从界面显示值直接抄。
2. **expect 禁止手算、禁止四舍五入**。取数流程：
   - 在 `.tmp/` 建临时测试文件，`console.log(JSON.stringify(solve(input), null, 2))` 实跑；
   - 把打印值**原样**（含全部小数位）抄入 `expect`；
   - 人工核对量级与物理合理性（方向、数量级、谁约束控制）；
   - **删除临时文件**。
3. `tolerance` 默认 `1e-9`（相对容差）；含随机性/数值积分/查表插值的公式可放宽，但要在 `source` 里写明理由。
4. `name` 说清工况特征与控制项（「声辐射约束控制」「阻尼校核递增 N」），失败时一眼定位。
5. `source` 注明出处：教材例题、标准号、论文算例或「自建算例」；论文/试验复现值与实现有系统偏差时，在 `assumptions` 说明偏差原因，benchmark 按修正后实跑值回归。
6. 数量：每个公式至少 1 条；有分支/多控制项的公式按分支各配 1 条（如 intakeHose 的「真空控制」「声辐射控制」两条）。
7. 修改 solve 导致结果变化：先确认修改正确 → 重新实跑取数更新 expect → 提交说明中写明变化原因。

## 7. 注册与验证清单

注册（`src/formula/registry.ts`）：

```ts
import { myFormula } from '../domains/structure/myFormula';
const ALL_FORMULAS: FormulaSpec[] = [ /* … */, myFormula ];
```

提交前逐项打勾：

- [ ] `npm run typecheck` 通过
- [ ] `npm test` 通过（新公式的 benchmarks 已被自动回归）
- [ ] `npm run dev` 打开界面：默认参数直接出结果；切换每个单位下拉结果合理；min/max 越界有提示
- [ ] `showIf` 逐腔参数随腔数增减正确显隐（输入、结果、CSV 三处）
- [ ] 导出 CSV：数值、单位、SI 列齐全
- [ ] 有 `curve` 的：曲线渲染、x 升序、与结果区峰值一致
- [ ] `assumptions` 覆盖全部工程近似与限幅
- [ ] `latex` 式号与 `description`、`solve` 注释一致
- [ ] 提交信息：`feat(<domain>): 新增××公式`，只含本公式相关文件
